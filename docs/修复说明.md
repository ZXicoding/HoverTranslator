# HoverTranslator 修复报告

> 目标：鼠标指向英语单词 → 自动识别光标下的那个词 → 美音朗读 + 悬浮窗显示中文翻译。
> 结论：**已修复并编译部署**。启动不再闪退，截图坐标、取词、翻译、朗读、悬浮窗全部打通；只差用户在系统设置里授予一次「屏幕与系统录音」权限。

---

## 一、它为什么完全用不了（3 个致命 bug）

### 1. 一悬停就闪退：在后台线程动 UI
崩溃日志（`~/Library/Logs/DiagnosticReports/HoverTranslator-*.ips`）里有两类，共 12 份：

| 崩溃 | 现场 | 原因 |
|---|---|---|
| EXC_BREAKPOINT / SIGTRAP<br>`Must only be used from the main thread` | `showPanel(at:word:zh:)` ← `URLSession` 回调线程 | 翻译请求的回调是后台线程，回调里直接 `setFrameOrigin` / 改 `NSTextField` |
| SIGABRT / `abort()` | `NSAlert` 初始化 ← `loadCaptureContent()` ← 后台 async 任务 | 只把 `runModal()` 丢回主线程，`NSAlert()` 本身仍建在后台线程 |

**修复**：整个 `AppDelegate` 标注 `@MainActor`，所有 UI/面板/朗读/弹窗都在主线程；耗时工作（截图、OCR、网络）用 `await` 挂起而不是切线程。`Swift 5` 模式下编译器不报错是这类 bug 长期潜伏的根因。

### 2. 悬停时 CPU 打满、疯狂重复朗读
旧代码每 0.18s `tick()` 一次，只要鼠标静止超过 0.45s 就**每 tick 都启动一个新的截图任务**，且没有「正在处理」保护：
实测一次截图+OCR 需要 200–400ms，于是鼠标一停就并发 5～10 个 ScreenCaptureKit 截图 + 同样多次翻译请求 + 反复 `stopSpeaking`/`speak`。

**修复**：改成边沿触发状态机 —— 鼠标移动后「武装」，静止 0.45s 只触发一次，处理完必须再移动才会再次触发；加 `busy` 单飞保护，同一时刻只允许一个截图任务；同一单词 1.2s 内不重复朗读。

### 3. 截图坐标翻错 + 只认主屏 → 拍的根本不是光标位置
旧代码：
```swift
let topY = displaySize.height - loc.y          // 错误：CGEvent.location 已经是「左上原点、y 向下」
```
而 ScreenCaptureKit 的 `sourceRect` 同样是左上原点（本次已实测验证：SCK 抓 y=0 与 `screencapture -R0,0,...` 像素内容完全一致）。于是截图区域被上下镜像，偏移约 320pt；同时悬浮窗把 y-down 值当 Cocoa y-up 用，窗口被画低了约 320pt，靠近屏幕顶部时直接跑到屏幕外。
另外 `contentFilter` 只取 `CGMainDisplayID()`，而用户光标常在第 2 块屏（Mi Monitor 1080×1920，Cocoa 原点 −1080,−231），坐标被 clamp 回主屏左边缘 —— 识别内容与光标完全无关。

**修复**：按 `NSScreen` 逐屏建立 `flippedFrame`（主屏左上为原点的全局坐标），光标落在哪块屏就用哪块屏的 filter；截图与悬浮窗各自做正确的坐标系换算；屏参变化（热插拔/改分辨率）自动重建。

## 三、现在的实际行为

1. 菜单栏出现 `译 ●`（绿色=开启）。
2. 鼠标**停下 0.45 秒**（不动），自动截光标周围 180×52pt → OCR → 选中光标下的英文单词。
3. 立刻弹出悬浮窗显示单词 + 「翻译中…」，同时美音朗读；中文回来后替换。
4. 3.6 秒后自动隐藏；移动鼠标再停下，可识别下一个词。
5. 光标停在同一处不会反复朗读/重复请求（必须移动才会再次触发）。

菜单项：
- `状态：已开启（点此暂停）`：暂停/恢复
- `屏幕录制权限：已就绪 / 未就绪`
- `测试翻译与朗读（hello）`：**不需要截图权限**就能验证朗读+翻译+悬浮窗
- `重新检测授权` / `打开屏幕录制授权设置`

## 三·五、权限踩坑（重要，本次真实遇到过）

**症状**：系统设置里 HoverTranslator 的开关是打开的，但应用仍反复提示"还没拿到屏幕与系统录音权限"。

**原因**：TCC 的授权记录是按「应用的代码签名身份」记账的。本机没有开发者证书，只能用 ad-hoc 签名，而 macOS 对 ad-hoc 应用实际仍按**二进制 cdhash** 匹配。只要重新编译过一次，旧授权就对应不上新二进制 —— 开关看着是开的，系统实际判定未授权（今天连续编译了 3 次，就留下了 3 条互不匹配的旧记录）。

**解决**（重置后重新授权一次，之后只要不再改源码重编译就一直有效）：

```bash
tccutil reset ScreenCapture com.example.hovertranslator
```

然后重新打开 `HoverTranslator.app` → 系统设置 → 隐私与安全性 → 屏幕与系统录音 → 打开 HoverTranslator → 完全退出应用 → 重新打开。

**避免再踩**：`./build.sh` 是增量编译，源码没改就不会重建，权限不受影响；只有 `--force` 或改了 `main.swift` 才会换二进制，此时需要按上面步骤重新授权一次。

> 想要"重编译也不丢权限"，需要用真实的 Apple 开发者证书或本机自签名证书签名（本机当前 `security find-identity -v -p codesigning` 为 0 个可用身份，故未采用）。

## 三·六、翻译联网问题（v1.2，2026-10-26 晚修复）

**症状**：悬停时经常提示"联网失败"，尤其是一些新词；有时慢很久才出结果。

### 根因（都已实测确认）

1. **三条翻译链路全都走系统代理**
   旧版 `URLSession` 用默认配置，会跟随系统代理（本机是 Clash `127.0.0.1:7897`）。
   Clash 退出、切节点、改全局模式时，有道 / MyMemory / Google **会一起失败**。
   旧版还没把「代理挂了」和「词典没收录」区分开。
2. **新词被误报成"网络失败"**（最误导的一条）
   有道词典没收录的生造词（如 `enshittification`）返回 200 但无释义；
   MyMemory 机翻对这类词会**原样返回英文**，旧代码把它当空结果，
   最后统一显示"（翻译获取失败，检查网络）" —— 其实是"没有中文释义"，不是网络问题。
3. **有道会自动纠错，旧代码却直接采信**
   实测 `delulu` 被有道 suggest 纠成 `delugu`，返回「n. 大洪水」。
   旧版不校验返回词是否就是查询词，会显示**错误释义**。
4. **串行等待 + Google 固定超时**
   旧版按 有道 → MyMemory → Google 串行等待；Google 在本机直连超时 4s、
   走代理返回 429，生词要白等 2~4 秒，体感像"卡死/失败"。

### 修复内容

| 项 | 做法 |
|---|---|
| 不再依赖代理 | 有道、MyMemory 使用**绕过系统代理的直连会话**（`connectionProxyDictionary = [:]`），直连失败才用跟随系统代理的会话重试 |
| 并行 + 快速取消 | MyMemory 并行发出，有道命中后立刻取消，典型 0.1~0.2s 出结果 |
| 重试 | 网络错误/429/5xx 重试 1 次（250ms 退避） |
| Google 熔断 | 连续失败后 10 分钟内不再尝试，避免生词每次白等 1.8s |
| 错误分型 | 真正网络失败 →「网络不通，翻译失败」；接口正常但无释义 →「词典未收录该词」 |
| 词形校验 | jsonapi/suggest 返回词必须与查询词一致（或前缀/后缀包含），拒绝 delulu→delugu 这类乱纠错 |
| 截断补全 | OCR 把长词截断时（transla）用有道 typos 补全为 translate，并显示完整词 |
| 截图加宽 | 半宽 90→110pt、半高 26→30pt，减少长词被边界截断 |
| 音标 | 有道 jsonapi 的美音音标显示在单词后面 |
| 网络诊断 | 菜单「网络诊断…」显示系统代理状态 + 三条链路的实时可达性与耗时 |
| 日志 | 每次翻译写 `~/Library/Logs/HoverTranslator.log`（自动轮转 512KB），反馈问题直接发这个文件 |

### 验证结果

- **停掉 Clash（系统代理已不可用）后连续翻译 15 次：成功 14、未收录 1、网络失败 0**（旧逻辑在这种情况下必然全部失败）。
- `hello` 0.21s，带音标 `/həˈloʊ/`；`serendipity` 0.17s；`rizz` 0.2s。
- `delulu` → 「幻想（网络用语）」（不再错成"大洪水"）。
- `transla` → 按 `translate` 补全并翻译。
- `enshittification` → 「词典未收录该词」，不再误报网络失败。
- 真实悬停（第二块屏）验证：面板显示 `area /ˈeriə/` + 中文，位置正确。
- 重建后 TCC 授权保持有效（identifier 型签名要求生效），无需重新授权。

### 已知限制

免费词典/机翻对**太新的生造词**确实没有中文结果（有道网页、MyMemory、Google 都试过），
这种情况下应用会明确提示"未收录"，朗读与音标仍可用。要覆盖这类词需要接入大模型翻译。

## 三·七、人名/地名的"背景解释"（v1.3，2026-10-26 晚）

**需求**：不只是把人名/地名翻译成中文，还要说明"它是什么、在哪个国家、为什么重要/有什么历史"。

### 做法

1. **识别是不是专有名词**
   - OCR 会同时返回光标下的词和它周围的**连续大写短语**（`New York`、`Albert Einstein`、`Baker Street`）。
   - 触发条件：词典释义里出现「首都/城市/省/州/人名/姓氏/物理学家/公司/大学/河/山/街…」等实体标记，
     或者识别到 2–4 个连续大写的专名。
   - 普通单词和菜单项（Harness、Edit）不会触发，避免噪音。

2. **取一句"背景"**
   - 首选：**中文维基百科**搜索接口 + 简介（`generator=search` + `prop=extracts`，`variant=zh-cn`），
     第一句通常就是"XX 是 YY 国的首都/某领域的某人"。
     例：`Kyoto → 京都是位于日本近畿地方的都市…其历史起于 8 世纪建立的"平安京"，于 794 年起被定为日本首都`。
   - 维基在国内直连被墙：请求走系统代理（Clash）；**代理不可用时**自动退回有道 `web_trans` 网络释义摘要
     （随翻译请求一起返回，不额外联网），同样能给出国家/城市/人口/地位等信息。
   - 结果按短语缓存；背景是异步获取的，翻译先出来，背景约 1–2 秒后补上。

3. **面板展示**
   - 三行：`单词 + 音标` / `中文释义` / `背景  …`；背景行字体更小、颜色更淡。
   - 面板高度按内容自适应（手动折行 + 精确行高计算，避免 NSTextField 自动换行在固定窗口里被截断）。
   - 有背景时面板显示时间从 3.6s 延长到 6.5s；面板位置仍避开截图区域，不会自我识别。

### 验证

- 真实屏幕悬停 "Kyoto"（用测试窗口渲染文字）：
  `Kyoto /kiːˈoʊtoʊ/` + `n. 京都（日本城市）` + `背景 京都是位于日本近畿地方的都市…`
- 人名：`Albert Einstein` → 背景「德国犹太裔理论物理学家，拥有瑞士和美国国籍。其创立了相对论及量子力学…」
- 地点：`Paris` → 「法国的首都及最大城市，同时是法兰西岛大区首府…」

## 四、打包与发布约定（每次更新都适用）

**原则：固定文件名，新版直接覆盖旧版，不堆积多版本。**

| 项目 | 约定 |
|---|---|
| 版本号 | 只改 `build.sh` 里的 `VERSION="x.y"` 一处；会写入 Info.plist 和 VERSION.txt |
| 分发包 | `dist/HoverTranslator-macOS.zip`（固定名）+ `dist/HoverTranslator-macOS/`（固定名） |
| 打包命令 | `./package.sh` —— 会先删除旧的 `HoverTranslator-macOS` 目录和 zip，再生成新的 |
| 常用文件 | `docs/使用说明.txt`、`docs/解决打不开的问题.command`（改完重新打包即可） |
| 本机安装 | 新版本直接覆盖 `HoverTranslator/HoverTranslator.app`，不保留旧版备份 |
| 版本记录 | 包内 `VERSION.txt` 记录当前版本号与构建日期（正文说明里不写死版本号） |

以后更新流程：
```bash
# 1) 改 main.swift / docs，必要时改 build.sh 里的 VERSION
./build.sh                          # 本机编译并覆盖安装目录里的 app
cp -R HoverTranslator.app /path/to/HoverTranslator/ && open /path/to/HoverTranslator/HoverTranslator.app
./package.sh                        # 生成固定名分发包（自动覆盖旧包）
```
